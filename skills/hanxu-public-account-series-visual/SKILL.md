## 使用者配置与独立使用

本文件同时保留使用者内部调用和独立用户模式，方法不分叉维护。使用者自用继续读取原对象、样本与状态工具；独立用户只使用自己提供的题目、观点、来源、正文、素材、授权、品牌及输出目录，不能读取使用者的私人库或替用户补造个人经历。下文使用者身份、业务方向、个人样本、品牌和参数是个人配置，独立使用不自动继承；使用者自己的原话、修改和已授权案例替代本人资料。原方法的事实、证据、适用边界与检查仍执行。

独立用户在自己的输出目录保存来源清单、版本、阶段结果和检查记录，可自行命名本地对象；不要求使用者内部对象ID、公司状态库或状态命令。材料已经齐全时按原顺序连续推进，确实缺失才补最小输入。内部Agent/上游/下游指本方法的阶段职责，独立任务按本次已授权范围执行，不需安装整套经营系统，也不自动建立定时任务或发布。安装包由本文件及其现有依赖生成；修改回原文件，导出目录不是另一份维护主档。

独立模式沿相同尺寸/图形/字体布局，品牌名、作者名、系列名及期数由使用者提供；缺省不带使用者身份，也不扫描使用者系列占号。提供--brand-label、--author、--series-name、--issue及输出目录；封面二不使用期数。用户需要支持中文字体；字体缺失时标明而不声称可读性通过。

# 公众号系列双图生成 Skill

归属：发布准备Agent（独立模式使用本次材料与本地记录）。执行标准：[发布准备执行标准](references/发布准备执行标准.md)。

本Skill负责公众号封面与固定系列正文头图。封面有两个可复用样式：原V0.7系列母版命名为“封面一”；“封面二”同时服务2.35:1消息列表和1:1转发卡片／公众号主页，横图保留原标题和上方小字“使用者AI”，方图显示该篇的简短主题。浅灰蓝与深灰蓝搭配，没有固定系列名或篇数，默认不放头像。普通生产按所选样式换标题及对象／版本字段；封面一还接收期数。正文插图由视觉排版Skill负责。

## 触发与输入

- 使用者要求生成公众号封面、正文头图、系列双图或前述两张图时，直接使用本Skill；只做这两张图时，不要求读取文章正文、其他历史文章、旧生成卡、经营简报或视觉排版（独立模式使用本次材料与本地记录）。
- 只要求封面时不生成正文头图。本人指定“封面一”或“封面二”时使用对应样式；只要求封面而未指定样式时默认“封面二”。当前任务已约定制作封面、随后仅给标题时直接生成，不重新询问风格。完整系列双图默认继续使用封面一，不因增加封面二自动替换既有文章发布包。
- 最低输入只有已确定的文章标题；完整发布准备中，标题可来自标题生成Skill（独立模式使用本次材料与本地记录）的授权AI选择，选择记录随图保留并标待使用者终审。当前文章对象、输出目录和版本若在当前任务中已经明确，直接沿用；没有明确时按当前日期建立不与既有对象冲突的公众号视觉对象，视觉修订从`V0.1`开始。
- 封面一及固定正文头图使用期数：本人明确给出时使用该值；否则优先复用对象原期数，再按现有系列视觉报告自动推算，结果写入报告。返修不增加期数，验收排除重复占号。封面二完全不使用、不展示、不分配系列期数。
- 使用者明确要求修改母版、颜色、构图、固定文字或尺寸时，按授权范围另建母版改版对象并保存可复用参数；不能把改版混入普通换字。增加第二种封面不覆盖封面一；新实图未得到采用反馈时不记为本人已批准成品。

## 锁定样式与固定文字

- 母版：封面一=`V0.7`；封面二=`COVER2-V1.5`，已由使用者确认长期沿用（独立模式使用本次材料与本地记录）。两种渲染逻辑均由`scripts/render_public_account_series_visual.py`调用，不另抄生成脚本，不重新搜索或挑选风格。
- 原版命名样图：封面一（独立模式使用本次材料与本地记录）。命名样图沿用原版实际PNG字节，不修改既有文章发布包路径。
- 两种封面上传母图均为`1283×383` PNG。左侧`900×383`为消息列表区域，右侧`383×383`为方形区域。封面一左侧以标题为第一视觉层、底部显示`使用者的个人商业系统　第NN篇`；右侧显示系列名和篇数。封面二的文字及图形只按下节执行。
- 正文头图：`1080×120` PNG，深海军蓝底，单行显示`使用者的个人商业系统　第NN篇`，整体水平、垂直居中，不放文章标题。
- 封面一固定视觉：深海军蓝`#17243A`、浅灰蓝、既定字体、三张错位经营卡片、系列标识、信息层级和安全区保持不变。封面二的配色与装饰只按下节参数执行。
- 标题过长时按所选样式的行数规则调整字号、字距和位置；保留标题原文，不改配色、图形或尺寸。不能用封面一的三行规则生成封面二。

### 封面二

- 完整上传图仍为`1283×383`，由左侧`900×383`横图和右侧`383×383`方图组成。上传后应分别选择：消息列表框裁左侧，1:1框裁右侧。上传母图本身不是平台显示比例，不能把整张1283×383缩放成2.35:1，也不能把后台自动选中的中心方形当作已验证结果。本人截图明确2.35:1用于消息列表，1:1用于转发卡片和公众号主页；最终平台裁切须以后台实际预览确认。
- 横图放原标题和其上方小字“使用者AI”；方图必须独立表达该篇主题，缩小后仍能知道在讲什么。整图没有“使用者的个人商业系统”等固定系列名、篇数或页码。当前已确认母版不放头像，主题信息优先。
- 标题最多两行。单行能清楚排下时保留单行；两行时上行明显短、下行明显长，不能上下字数近似或拆成三行。先按完整语义与标点决定断行，再调整字号；实现默认上行字符数不超过下行的70%，该比例是执行参数，不冒充本人指定数值。自动断行优先上半段语义标点，不拆AI等连续英文词；必要时用两个`--title-line`明确断行，拼接必须逐字等于原题。
- 左侧改为浅灰蓝渐变底（`#F5F7FA`至`#DDE7EF`），用低对比度的局部光晕、斜面和细线形成背景层次，避开标题。原标题用深灰蓝`#24364B`，左对齐、垂直居中；字体最多46px、字重600、行距约1.38倍，长下行再适配字号。保留约80px左边距，不用大字占满画面，不放底部系列文字或粗重装饰。
- 方图用深灰蓝渐变（`#263D56`至`#1C2D42`）和少量低对比细线，主体为一至两行简短主题。第一行最多62px，第二行最多44px，字重600／400；每行最多8个字符，长句适配字号。每行水平居中，所有文字作为一个整体垂直居中于383×383方形，不能沿用横图的左对齐；当前生成器按实际字形的可见边界校准位置，行间留约22px。执行时由AI从原标题提炼主题短句，不能新增事实、收益保证或改变问题；例如原标题“想用AI赚钱，先想清楚别人为什么付钱”对应“AI赚钱／谁来买单”。这是方图摘要，不是修改文章标题。用重复的`--square-line`传入，给标题后由AI自动完成提炼，不要求本人补小图文案。原题不足8字可直接沿用。主题优先于装饰和头像，当前母版无头像，不调用头像素材。
- “使用者AI”固定放在左侧标题上方，与标题左边界对齐，约18px小字、正常字重、低饱和灰蓝，明显小于标题；不放在头像下方。默认由生成器写入，不必每次额外给名字。不写“含蓄AI”或“韩旭AI”。本人明确不要小字时可用`--brand-label ""`省略。
- 已确认样图见封面二（独立模式使用本次材料与本地记录），来源及字节绑定见采用记录（独立模式使用本次材料与本地记录）。常规换标题直接沿用该母版，不重新询问样式。需直接查看两个裁切图，并将方图缩至96×96及64×64检查主题辨识；本地预览不能冒称已完成微信后台裁切。

## 唯一执行链

1. 先读[发布准备执行标准的公众号系列双图标准](references/发布准备执行标准.md)，再确认标题原文及所选样式；只有封面一／固定头图任务需要期数。
2. 按任务选择生成范围。标题外的对象、版本和输出参数使用当前对象值；缺省值由生成器按本Skill规则建立。普通生产不读取其他工作流文件。只做封面二时：

   ```bash
   python3 scripts/render_public_account_series_visual.py \
     --title "<最终标题>" \
     --cover-style 2 --cover-only \
     --square-line "<主题关键词>" --square-line "<该题核心问题>" \
     --delivery-dir "<交付目录>"
   ```

   封面一的单图任务将`--cover-style`改成`1`，同样带`--cover-only`，可带`--issue auto`。已有对象返修传原`--object-id`，封面一保持期数；封面二不推算期数。样式使用不同运行目录，不能同目录覆盖另一种封面。完整系列双图使用以下原有命令：

   ```bash
   python3 scripts/render_public_account_series_visual.py \
     --title "<最终标题>" \
     --issue auto \
     --delivery-dir "<交付目录>"
   ```

   已有对象或明确期数时可补充`--object-id`、`--object-dir`、`--issue`、`--visual-revision`、`--article-version`和`--title-version`；标题需要人工指定断行时才重复传入`--title-line`。
3. 仅封面任务产生上传母图和两张内部裁切检查图，完全不生成正文头图；对外交付一张成品，按样式命名为`封面一.png`或`封面二.png`。完整双图任务仍产生上传母图、正文头图及两张裁切检查图，对外交付原命名`01-公众号封面图-1283x383.png`和`02-正文头图-1080x120.png`。裁切图只留运行目录。
4. 每次输出`config.json`、`render-report.json`、实际标题、样式名、母版版本、尺寸和哈希。封面一另记期数来源；封面二记期数不适用、标题行数、方图短句、左上小字原文及两个裁切区坐标。三张封面相关图片来自同一次渲染，不混用样式。交付只展示一个当前成品，内部试稿和旧版不混在回复里。
5. 完成后复读[公众号系列双图标准](references/发布准备执行标准.md)，直接查看本次生成的全部实际PNG并核对报告。仅封面任务核对三张，不要求正文头图；完整双图核对四张。通过后按本人要求的范围交付并停止。

## 交接与机器字段

- 只做两张图时，交付：最终标题、推算或明确的期数、两张成品绝对路径、运行目录、`render-report.json`和本次检查结论；完成本次图片任务后停止，不强制继续完整发布准备。
- 只做封面时，交付所选样式的一张封面PNG和必要检查记录；不额外生成头图、正文、PPT插图或完整发布包，不修改原文章已绑定的封面。用户给标题后按上述默认直接生成封面二；需要旧版可明确说“封面一”。
- 完整发布准备时，向视觉排版（独立模式使用本次材料与本地记录）交接`series_cover_ref=公众号封面母图`、`article_header_ref=正文头图`、`series_issue=两位数期数`和`series_visual_check_ref=双图检查记录`。发布包仍由视觉排版Skill汇总。
- 完整双图任务中标题或期数改变时，两张旧成品同时失效，必须整组重出；不得混用不同修订的封面和正文头图。仅封面任务只返修本次封面，不因此补造头图。

## 返回、停止与清理

- 标题尚未确定：返回标题生成或等待使用者给出标题，不生成正式双图。
- 自动推算发现同一期数被不同有效对象占用，或现有记录互相冲突：停止交付并只报告期数冲突，不自行覆盖。
- 普通标题换字不触发改版；明确改版时保留当前批准母版，另建改版对象并等待使用者确认后再替换。
- 最终采用后保留两张成品、运行配置、报告和当前修订源文件；错误尺寸、重复导出和已替代成品移入可恢复废纸篓。


## 随包原渲染器

先在本目录运行`npm install`安装Sharp，再调用`python3 scripts/render_public_account_series_visual.py --title "已确定标题" --cover-style 2 --cover-only --square-line "主题" --brand-label "自己的品牌" --delivery-dir "用户输出目录"`。封面一双图使用`--cover-style 1 --issue 1 --author "姓名" --series-name "系列名"`。只换必要文字，不重新设计母版。

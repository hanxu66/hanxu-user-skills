## 当前版本

**用户试用版 v0.1.5，2026-10-30。** 目录标识沿用 `hanxu-script-agent`，展示名为“韩叙 · 短视频口播文风助手”。

本版提供论点澄清、论证与证据组织、短视频结构、完整口播写作、本人样本学习、无历史语料的对话与改稿校准，以及本地作者记录接续。使用现有写稿方法并提炼自然表达研究中的可迁移操作，私人原始直播语料不随包发布。

v0.1增加快速上手、语料与校准、完整虚构演示、常见问题及反馈说明；v0.1.1补Windows和WorkBuddy入口、宿主能力降级、路径与编码适配。本轮在macOS WorkBuddy 5.9.3真实使用后，明确ZIP选择及同名更新步骤；分享包仅导出独立用户章节，原内部方法完整保留；补强第一人称细节的来源核对与虚构材料标记。每次打包的具体构建版本和来源哈希见 [SOURCE.json](../SOURCE.json)，合集构建版本见 [仓库首页](https://github.com/hanxu66/hanxu-user-skills#readme)。

v0.1.2修复同消息、相近话题的材料用途混淆：先区分本题内容与表达样本，样本里的历史请求不作为当前指令，事实与建议不自动进入新稿；证据边界调整不替作者确认认错或撤回立场。首次输入示例仍支持一条消息提交两类材料。v0.1.2已补macOS WorkBuddy 5.9.3的新版导入、配套文件读取和对话交稿试验，范围与本次终端故障见[平台指南](platforms.md#当前验证状态)；既有v0.1.1试验不自动证明新场景通过。

v0.1.3调整默认交稿形式：只给可直接复制的口播正文，去掉段落标签、括号提示和默认随稿分析；用户需要时再展示说明和记录。事实核对、论证与文风校准仍在后台执行。

v0.1.3的完整原案复测出现样本内容混入，纯正文格式通过但材料隔离失败。v0.1.4据此补强写前的原文范围与事实清单、仅提取语言特征，以及交稿前每项事实的本题出处核对；不能用较简单的合成任务替代原案复测。

v0.1.5增加全文去重、断言证据范围与本题时长预算检查，避免仅格式和样本隔离通过就交稿；过去的两项通过不代表整体内容质量已验证。时长要求按每条任务处理，文字预算与真实朗读分别记录。

真实客户端试验仍使用虚构作者与反馈：它验证软件中能否执行这些动作，不是目标用户试用结论。首稿审读发现过内部固定格式带入、材料外细节及过强推断；已据此修正导出/核对方法并完成返修。因此使用时仍须本人核对判断、事实与表达，不以程序PASS代替审稿。

模拟输入不是客户案例或真人评价；AI重新审读也不是另一位真人的独立验收。[演示页](examples.md)另为文档编写的虚构示例，不计入验证样本。

## 建议怎样试用一次

选一个真实要讲的题目，提供自己的判断和依据，拿到完整稿后挑一两句不会说的话修改。再用另一条新题，检查是否能沿用合适的表达偏好，同时保留新题事实。

可以观察：作者是否愿意这样讲；论据有没有真正支撑判断；听者能否复述核心意思；局部改稿有没有牵动无关内容。没有必要为试用先发布视频，也不用把“满意”推断成平台效果。

## 提交反馈

可以在 [GitHub Issues](https://github.com/hanxu66/hanxu-user-skills/issues) 提交问题，也可以先把以下模板留在自己目录。不需要提供私人语料库、完整客户信息、账号凭据或支付信息。

```text
【版本】SOURCE.json里的构建版本；用户试用版v0.1.5
【使用环境】Windows/macOS版本；AI工具与版本；是否能读写文件、运行Python
【这次想完成什么】题目、给谁听、希望保留的判断
【输入类型】本人历史样本／本轮对话／没有样本
【具体问题】哪一句或哪一步不对
【我的说法】原句 → 我会怎么说（有则提供）
【修改范围】只改措辞／改结构／改论点或论证
【适用范围】仅这条／本人长期偏好／暂不确定
【预期与实际】想得到什么，实际得到什么
【可公开材料】只贴必要且已脱敏的片段
```

如果问题出在安装、文件缺失或校验，附错误文字和相关版本即可。文风问题优先给成对句子及自己的改法；“不像我”可以作为反馈起点，再具体指出不适配位置。不承诺固定回复或更新周期，修复与调整按实际反馈和证据推进。

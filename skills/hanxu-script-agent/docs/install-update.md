# 短视频口播文风｜安装与更新

> 方法版本：0.1.7。安装完整目录，个人资料与技能文件分开保存。

## 1. 安装完整技能

**本地包：**解压本版ZIP，找到直接含有 `SKILL.md` 的 `hanxu-script-agent` 文件夹，把实际位置交给Codex：

```text
请检查我提供的 hanxu-script-agent 完整文件夹，把它安装到当前电脑适合我的本地Skill位置，保留配套引用。先核对现有安装；有旧版或本地修改就保留并移到技能发现目录外备份，不覆盖个人资料、其他Skill或维护源码。失败恢复旧版，成功告诉我实际位置和读取到的版本。
```

**从GitHub安装：**将下段复制到自己的Codex对话中：

```text
请用 $skill-installer 从 https://github.com/hanxu66/hanxu-user-skills/tree/main/skills/hanxu-script-agent 的所指技能子目录安装 短视频口播文风 Skill，技能标识为 hanxu-script-agent。先识别当前实际执行的电脑和系统，保留完整目录，核对入口与配套引用。已有同名或旧名版本时先确认正在使用的位置、保留本地修改并备份到技能发现目录之外；不要覆盖个人资料、维护源码或其他Skill。安装失败恢复旧版；成功后报告实际位置和读取到的版本。
```

不要只复制 `SKILL.md`，也不要把整个开发仓库误当技能。GitHub源码中的技能位置是 `skills/hanxu-script-agent`；下载Source code ZIP时按这个位置找到入口，不把上层包装目录一起安装。

安装器可能有自己的默认位置，以本机实际报告为准；无需为匹配教程再复制第二份。手动安装只选一个范围：

| 范围 | 入口位置 |
|---|---|
| macOS当前用户 | `~/.agents/skills/hanxu-script-agent/SKILL.md` |
| Windows当前用户 | `%USERPROFILE%\.agents\skills\hanxu-script-agent\SKILL.md` |
| 仅当前项目 | `项目目录/.agents/skills/hanxu-script-agent/SKILL.md` |

## 2. 确认读到了哪一版

安装完成后，在下一轮或新对话输入：

```text
使用 $hanxu-script-agent。先确认实际读取的Skill位置、包内版本及当前依赖，再根据我的材料开始。不要把能读到说明当作所有软件或平台已经连通。
```

未出现时先核对入口层级、引用文件及重复安装，再重开Codex。`$`是Codex对话里的技能选择方式，不是在终端执行的命令。方法版本以包内说明为据；存在 `SOURCE.json` 时同时报告构建版本，未知版本不猜。

## 3. 开始本次任务

可加载完整Skill及参考文件的Codex或WorkBuddy；写稿无需Python。可选正文证据校验只用Python标准库，包内不含转写、配音或声音克隆服务。

```text
用 $hanxu-script-agent 写一条口播。我想讲【题目】，给【观众】听；我的看法与真实材料是【自己的话】。请理清论点、论证和结构后交完整稿。有我的样本就学习，没有就用当前对话和改稿校准。作者记录保存在我自己的内容目录。
```

先指定一个自己的工作目录，放入本次材料和输出；安装目录只放技能。安装成功、宿主能读到文件、工具连通和最终结果合格分别核对。AI工具及可能的外部服务费用按自己的账号承担。

## 4. 更新、保留资料与失败恢复

1. 先记录当前安装位置及版本，确认工作目录里的口播试用/中的作者表达记录、成对稿件、来源和反馈仍可读取。如果个人资料误放在安装目录，先保留到独立工作目录再处理更新。
2. 比较新版与旧版，保留对Skill文件的本地修改；不自动把用户修改合并进新版规则。将完整旧版备份到所有技能发现目录之外，不把备份留在 `.agents/skills`、旧的 `.codex/skills` 或其他正在扫描的位置。
3. 仅替换这一个Skill的文件，保留工作目录和原维护源码。安装器提示目标已存在时不要强制覆盖；先核对旧版和备份。安装或引用核对失败时，移出不完整新版，恢复刚备份的旧版，不用删除用户资料重试。
4. 重新读取实际版本，先完成一个小任务或局部修改，再继续原来的工作；不要把验证更新扩成一次完整重做。

```text
请核对 hanxu-script-agent 的当前安装与新版，先备份旧版和我的修改到技能发现目录之外，只更新这一项。保持我的工作目录不变，失败恢复旧版。更新后读回实际版本，再从我指定的记录继续，不重新收集已经提供的背景。
```

## 5. 常见问题

| 情况 | 处理 |
|---|---|
| 同名Skill出现两份 | 确认实际使用位置，备份移出所有发现目录，只保留一份活动安装。 |
| 安装目录多套一层 | 确保 `hanxu-script-agent/SKILL.md` 直接存在，保留其完整配套目录。 |
| 以前的记录找不到 | 指定原工作目录或提供可复制记录；安装Skill不会自动同步个人资料。 |
| 当前工具能力不足 | 说明缺的是文件、搜索、音视频、软件连接还是账号权限，保留已完成结果，处理本次必要缺项。 |
| 提示升级会覆盖目标 | 先比较与备份，不强制覆盖，不将卸载或删除当作资料备份。 |


## WorkBuddy：Windows 与 macOS 的安装、更新和接续

Windows 11 的 WorkBuddy 5.9.3 曾以资料包v60实际完成以下操作；macOS 5.9.3 的 ZIP 导入、写稿、改稿及记录接续也有实测。历史流程试验不能证明当前v0.1.7已在Windows通过首稿质量验收；各系统、包版本与限制见[平台指南](platforms.md#当前验证状态)。

1. 从 [WorkBuddy 官网](https://www.workbuddy.cn/)下载适合本机的客户端并登录。使用你自己的账号和可用额度，本 Skill 不附模型额度，也不要求购买付费套餐。
2. [下载完整 Skill ZIP](https://github.com/hanxu66/hanxu-user-skills/raw/main/packages/hanxu-script-agent.zip)。打开「专家·技能·连接器 → 技能 → 添加技能 → 上传技能」，点底部「选择 ZIP 文件」，选择这个原包。等待常规检测，按实际结果处理，再继续安装；不要跳过检测。
3. 在「已安装」列表确认 `hanxu-script-agent` 已启用。展示名是“短视频口播文风助手”，不是另一个技能。
4. 建一个自己的内容文件夹。WorkBuddy 新任务下方选择「选择工作空间 → 打开本地文件夹」，绑定它。稿件、来源、反馈和作者表达记录都放这里，不能放到 Skill 安装目录。多人各有子目录。
5. 开始写稿时说“请使用已安装的短视频口播文风助手（hanxu-script-agent）”，附题目、听众、判断和材料即可；不用输入 Codex 的 `$` 标记。没有历史语料也可开始。也可在输入框的「+ → 技能」中选择已安装的 `hanxu-script-agent`。选择技能成功只说明调用入口可用，仍须核对实际结果。

**先试一条再用于正式内容：**正常写稿应直接交完整正文。点击回复下方「复制」，粘到空白文本中，检查有没有混入“我先读取”、检查或保存说明；只看最后气泡不够。再核对原材料是否真的支持稿中的结论，局部改稿后检查范围外正文是否保持。不同模型的执行结果可能不同，按[实际验证范围](platforms.md#当前验证状态)选择；本 Skill 不附赠额度，也不要求为复测升级或充值。

**更新时：**先保留对旧 Skill 的本地修改，并核对独立工作目录中的作者记录、稿件和反馈仍可读取。5.9.3 会拒绝重复导入同名技能，正常做法是「已安装 → hanxu-script-agent → … → 卸载」移除旧 Skill，再按上述 ZIP 入口导入新版并启用。只更新这一个 Skill，不删除内容工作目录，也不自行改客户端内部文件。旧包保留在安装发现目录之外，导入失败可重新导入旧包恢复。

**更新后、换聊天或换题：**新建任务并重新选择同一个内容工作空间。可复制：

```text
请使用已安装的短视频口播文风助手（hanxu-script-agent）。
这是【作者】的新任务，先读取当前工作空间【作者子目录】中的作者表达记录和必要反馈，只沿用适用于本题的已确认偏好。
新题是【题目】，给【听众】听；我的判断和本题材料是【内容】。
请理清论点、论证和结构，写完整口播，新稿另存；旧题事实不要搬入。
```

安装同一个包不会自动同步作者资料。跨设备需要自己携带记录与必要材料，或让新设备能访问它们；未选同一工作空间时先找对目录。方法版本和构建版本可在技能详情、包内说明与 `SOURCE.json` 查看。默认写稿不要求每次额外发送版本或检查报告；需要查看时再单独询问。

Codex目录与发现机制依据[OpenAI官方说明](https://learn.chatgpt.com/docs/build-skills)。本指南统一安装与更新方式，原有方法、功能、参数、公开边界和各客户端验证范围保持原说明。

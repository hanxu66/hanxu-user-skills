# 韩叙 · 短视频口播文风助手

用户试用版 v0.1。把你的想法整理成讲得清楚、适合你说出口的短视频口播稿。

- **适合谁**：内容创作者、知识博主、需要出镜表达的专业人士。
- **提供什么**：本次想讲的题目、目标观众及自己的看法或材料；表达样本可选，没有也能开始。
- **得到什么**：核心论点、论证依据、内容结构、完整口播稿，以及可继续修改的个人表达记录。
- **使用条件**：需要可用的 Codex，以及你自己的观点和材料。

先看[中文使用介绍](README.md)。执行从下方“独立用户试用入口”开始；只读取各Skill的独立用户章节及所需引用，内部工作流章节不作为用户前置条件。安装标识沿用 `$hanxu-script-agent`。

## 使用者配置与独立使用

本文件同时保留使用者内部调用和独立用户模式，方法不分叉维护。使用者自用继续读取原对象、样本与状态工具；独立用户只使用自己提供的题目、观点、来源、正文、素材、授权、品牌及输出目录，不能读取使用者的私人库或替用户补造个人经历。下文使用者身份、业务方向、个人样本、品牌和参数是个人配置，独立使用不自动继承；使用者自己的原话、修改和已授权案例替代本人资料。原方法的事实、证据、适用边界与检查仍执行。

独立用户在自己的输出目录保存来源清单、版本、阶段结果和检查记录，可自行命名本地对象；不要求使用者内部对象ID、公司状态库或状态命令。材料已经齐全时按原顺序连续推进，确实缺失才补最小输入。内部Agent/上游/下游指本方法的阶段职责，独立任务按本次已授权范围执行，不需安装整套经营系统，也不自动建立定时任务或发布。安装包由本文件及其现有依赖生成；修改回原文件，导出目录不是另一份维护主档。

## 独立用户试用入口｜短视频口播文风 v0.1

本入口适用于经营系统之外的使用者，接收用户已确定的题目或明确委托的改稿，把论点、论证、结构与个人表达接成完整口播稿。没有内部选题卡也可开始；还没有明确判断时先通过对话澄清，不代替用户宣称立场。

1. 先读[脚本执行标准第0节](references/脚本执行标准.md)，再由[表达学习与应用](references/表达学习与应用.md)接收本次材料与作者记录：有本人样本就学习；没有就用当前对话和后续改稿逐步校准。材料齐全直接写，不增加风格确认闸门。
2. 调用[观点立意](references/观点立意.md)，明确唯一判断、理由、证据及证明范围。可同轮完成；只有影响内容成立的真实缺口才询问用户，不因缺历史语料停止。
3. 调用[内容结构](references/内容结构.md)，把论证安排成开头、承接、推进与收束；接着调用[逐字稿](references/逐字稿.md)，应用个人表达，交付完整稿和必要说明。第0节检查不通过返回缺陷所属阶段；不逐阶段要求回复“继续”。
4. 收到反馈按实际归属返修，并交表达学习保存本人改法；新题回读本作者记录。稿件交付停在待作者采用或修改，不索取原片，不自动进入剪辑或发布。

独立模式执行上述入口和各Skill对应独立章节。下方内部生产的选题状态、公司库、AI主题、清理与拍摄交接不作为独立用户要求；不自动删除或关闭用户稿件。使用者内部模式仍走下方原链路，本试用入口不替换私有直播分支或默认自用配置。

## 原方法与执行流程

- 标识：`short-video.agent.script`
- Skill顺序：[观点立意](references/观点立意.md) → [内容结构](references/内容结构.md) → [逐字稿](references/逐字稿.md)。
- 结果标准：[脚本执行标准](references/脚本执行标准.md)。

本Agent只负责输入接收、Skill顺序、状态接力、人工闸门、返修和清理。本Agent不定义立意、结构、表达或写稿方法，也不定义结果判定；操作只读当前Skill，判定只读执行标准。

## 触发与输入

每次回复前按任务对应表（独立模式使用本次材料与本地记录）重新读取本Agent、本次业务Skill与[脚本执行标准](references/脚本执行标准.md)；同一话题的讨论、反馈和返修同样适用。

- 生产只接收选题Agent交付的`已选`选题卡，或使用者明确要求返修的当前脚本。收到开头标注、改分、批次完成、学习要求或选题Agent交来的开头学习时，路由[表达学习与应用](references/表达学习与应用.md)的“开头标注学习更新”，归纳并更新唯一主责规则；同轮回交原请求的学习结果。纯保存状态查询只核验；没有已选题时不因此启动写稿或推进生产状态。标注学习是标准维护的辅助方法，不是已选题到逐字稿的必经环节；日常开头生产按脚本执行标准执行。
- 输入包含已选题及授权、来源、受众、判断和依据；外部路线另带改造模式、资产引用、核心与结构参考。先路由[表达学习与应用](references/表达学习与应用.md)召回相关历史样本和反馈，再开始立意；缺真实来源退回上游，不把缺少本人新增观点作为默认阻塞。
- 接收候选准入依据和已研究材料后，仅将立意所需的真实缺口退上游补充；不为流程形式重复来源搜索或另造核心观点。候选判断与最终立意分工只读筛选推荐和观点立意Skill。

## 唯一执行链路

1. 接收`已选`及证据，按表达学习与应用Skill建立本对象应用记录，然后路由到[观点立意](references/观点立意.md)。
2. 观点立意步骤由执行标准判定为`通过`后提交`立意完成`，同轮路由到[内容结构](references/内容结构.md)。
3. 内容结构步骤由执行标准判定为`通过`后提交`结构完成`，同轮路由到[逐字稿](references/逐字稿.md)。
4. 接收逐字稿Skill对当前正文的独立复核及绑定当前对象／版本的结果，实际开头、推进或收获有失败／未验证项时退回其所属阶段；复核通过后才提交`脚本完成`并记录表达形式。真人口播接拍摄输入，动画视频接已确认稿与画面方案，由剪辑Agent调用动画视频制作Skill。
5. 任一步为`失败`时退回该缺陷所属Skill，并按影响范围使下游状态和证据失效；为`未验证`时保持当前状态。
6. 一次命令可以连续完成多个Skill，但不能改变顺序或越过状态；返修只维护一个当前版本。

- 收到使用者修改稿、否定、实际口播或采用反馈时，同轮路由表达学习与应用Skill保存差异与学习；无需等待发布数据。涉及观点、结构变化时按影响范围返修，学习入库后继续当前可执行生产。

## 每一步的固定读取与检查

1. 进入观点立意、内容结构、逐字稿的每个业务步骤前，按总入口读取规则重新读取本Agent、执行标准和当前Skill文件，再执行本步；不能以本轮早先读过代替。
2. 完成后再读同一执行标准章节，重新打开当前产物和来源检查；通过后才保存检查点、提交状态并进入下一Skill。
3. 返修、失败重试、断点恢复和切换Skill均重新执行步前双读；同一步内连续写作或修改不机械重读全文。

## 状态接力

- 观点立意、内容结构和逐字稿分别提交`立意完成`、`结构完成`、`脚本完成`。三个状态返回`AUTO_CONTINUE_SAME_TURN`时立即进入下一Skill，不形成额外人工闸门。
- 真人口播的`脚本完成`仍接人工拍摄闸门；实际原片到达并核对后才提交`已拍`。动画视频记录`production_form=animation`及本次稿件确认依据，交接字段按动画视频制作Skill定义，交剪辑Agent创建／锁定工程后直接进入`剪辑中`，不伪造拍摄事实。
- 真人口播停在拍摄闸门时，按入口的反馈提示（独立模式使用本次材料与本地记录）显示`稿件已交付，待原片`，说明所需原片和对应稿件；已提供的素材不重复索取，真实原片到达后交剪辑Agent。
- 任何退回都回到真实缺陷所属Skill；下游逐字稿、拍摄对照或旧检查随受影响范围失效。状态接力返回`AUTO_CONTINUE_SAME_TURN`时直接进入下一内部阶段，不要求使用者复述背景。

## 状态与交接

具体通过/失败条件只读[脚本执行标准](references/脚本执行标准.md)。本节只规定状态字段、人工闸门和交接动作。

- 进入逐字稿前须存在`已选`、`立意完成`和`结构完成`的当前状态引用；缺少任一引用就停在相应上游。
- `脚本完成`只表示稿件通过脚本标准，不等于本人采用、真实拍摄或实际时长成立。动画分支的`script_approval_ref`须绑定本人已确认／明确委托制作的当前完整稿件；未确认稿件只等该最小反馈，不索取真人原片。
- 使用者直接给已确认逐字稿并要求动画视频时，剪辑Agent接独立入口，从该稿开始制作；本Agent不补造未实际运行的选题、立意和结构状态。
- 使用者拍摄后，实际说出的内容成为剪辑阶段最高事实，确认稿只作对照。
- 阶段末证据由当前Skill生成并由执行标准判定；本Agent只保存引用，不复制检查内容。

## 返回、停止与清理

- 立意不成立退回立意；结构不连续退回结构；文风问题只在逐字稿修复。
- 使用者否定且明确不再改：吸收可泛化学习后标记`未采用`并清理该稿及中间检查。
- 新版本被采用或已拍后，旧AI草稿和旧检查标记`已替代`并清理；保留实际拍摄稿、已发布稿和可复算的累计学习证据；清理旧AI稿前必须已有成对正文或足以复算差异的快照，不能只剩一条总结。
- 没有反馈且使用者转向新题、完成拍摄其他稿或关闭本周：原稿不再保持待反馈，按未采用关闭。

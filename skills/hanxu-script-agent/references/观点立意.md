## 独立用户的论点与论证

独立试用只执行本节，检查读[脚本执行标准第0节](脚本执行标准.md)；公司内部的选题准入、案例限定和状态字段不属于本包。

1. 从本次原话与材料提取目标观众、要回答的问题和作者判断。已有明确判断保持原意；只有题目时，用最小追问让作者说清“你怎么看，为什么”。用户明确委托协助推敲时可提出候选判断，标待本人选择，不以风格学习推定作者立场。发现原文有过度保证或论证缺口时，指出具体主张和最小影响范围；收窄证据强度不等于作者已承认过错。未经确认，不把建议的新解释、他人动机或“我说错了、我收回”的立场写成作者自己的结论；能在原主旨内修复就继续成稿，确需换主判断时只确认该项。
2. 分开列已发生事实、作者观察、推测、建议及假设，定位来源。保留材料原有的虚构、演示或假设标签，不能改记为本人亲历。写作前留下本题事实清单与原文依据，尤其核对第一人称的具体动作、方位、程度、对话和结果；材料没有说的细节与结果保持未知，不能为了讲顺补齐。新增解释与经历事实分开，不把一般推理改成“我做完后发生了什么”。本人真事、可核对且获准使用的外部材料均可支持论证，外部观点在正文归因；没有个人成功案例也可用有依据的分析。不把类比、假设或风格样本中的旧事实当成效果证据。材料不足时补最小缺口、缩小结论或删除无依据主张，不编造案例。
3. 写清每项“论点 → 为什么 → 依据 → 能证明到哪一步”。按本题选择具体论证方式：因果解释补机制及可能的其他原因；比较说明比较对象、条件和差异；案例讲清过程与证明范围；类比说明相似关系与不适用处；反例用于检验边界。可以组合，不凑全套，不把发生先后当因果，不以一个案例推出人人有效。偏好某种论证方式不能凌驾证据。
4. 留下最强疑问或反例及作者能回应到的范围，用日常话写出观众看后具体改变哪个理解或动作。将唯一判断、论证链、证据、边界和收获保存为本题上游依据；检查后交内容结构。没有调查依据时不编造“大家都以为”的普遍误区，观点成立也不要求强行反转。

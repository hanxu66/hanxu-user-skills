## 独立使用的配置边界

独立用户沿本文件的方法与检查，以自己的已确认任务、原话、真实材料及输出目录执行。使用者身份、业务主题、样本库、专名纠正表、品牌及字幕/字体/美颜/美体/速度/音量数值仅属于使用者自用配置；其他用户保持自己的原片/原工程值或本次明确选定值。没有个人历史样本时校准本轮原话，不虚构过去的修改和效果。不调用公司状态库、自动化或私有客户资料；各阶段凭证保存用户本地记录。

# 观点立意 Skill｜锁定这一条视频唯一要证明的判断

- 标识：`short-video.skill.angle`
- 所属Agent：[脚本](../SKILL.md)
- 执行标准：[脚本执行标准](脚本执行标准.md)

本Skill只定义观点立意的执行流程。每个大步骤前先读执行标准对应章节，再读本步；完成后复读执行标准并对照已选题、来源和立意卡。

## 独立用户的论点与论证

独立试用只执行本节，检查读[脚本执行标准第0节](脚本执行标准.md)；下方公司选题准入、本人或学员案例限定和状态字段用于内部模式。

1. 从本次原话与材料提取目标观众、要回答的问题和作者判断。已有明确判断保持原意；只有题目时，用最小追问让作者说清“你怎么看，为什么”。用户明确委托协助推敲时可提出候选判断，标待本人选择，不以风格学习推定作者立场。
2. 分开列已发生事实、作者观察、推测、建议及假设，定位来源。本人真事、可核对且获准使用的外部材料均可支持论证，外部观点在正文归因；没有个人成功案例也可用有依据的分析。不把类比、假设或风格样本中的旧事实当成效果证据。材料不足时补最小缺口、缩小结论或删除无依据主张，不编造案例。
3. 写清每项“论点 → 为什么 → 依据 → 能证明到哪一步”。按本题选择具体论证方式：因果解释补机制及可能的其他原因；比较说明比较对象、条件和差异；案例讲清过程与证明范围；类比说明相似关系与不适用处；反例用于检验边界。可以组合，不凑全套，不把发生先后当因果，不以一个案例推出人人有效。偏好某种论证方式不能凌驾证据。
4. 留下最强疑问或反例及作者能回应到的范围，用日常话写出观众看后具体改变哪个理解或动作。将唯一判断、论证链、证据、边界和收获保存为本题上游依据；检查后交内容结构。没有调查依据时不编造“大家都以为”的普遍误区，观点成立也不要求强行反转。

## 触发与输入

- 来自标题/介绍/标签调研的已选题标记`analysis_scope=metadata_only`，先依据本人已确认判断、真实业务材料和案例形成立意；作者完整观点、论证与结构未知，不默认获取对标口述内容。只有另行明确借具体外部观点/结构时按该具体任务核验来源，不回到日常对标Skill恢复深读。

- 公众号文章改编回读全文及文章阅读卡，保留原核心判断、证据与边界，再明确当前短视频的受众、具体问题和收获；已选文章可复用已有事实，不为流程形式重新找题。

- 已选选题卡、来源材料和可核对的使用者/已授权客户事实。

## 唯一执行链路

1. 先接收已选题的准入依据、锁定核心及现有来源研究，回读实际证据，标明可直接继承项与真实缺口；按[表达学习与应用](表达学习与应用.md)召回相关观点、本人表达样本及已解决问题的场景／案例／方法原始材料，在应用记录中写明采用与不采用理由，再写出目标观众原来的理解。把选题卡中的具体问题、题面预期收获及实际采用的复盘反馈，分别对应到下方立意五项的判断、证据与用户收获；个人实践作为解释用户问题的证据使用，不能只把作者总结改成标题。本步确定最终可讲的立意与证据用途，不把已有候选研究重新搜索一遍；仅缺口、证据变化或本人修改引发实质补读和返修。
2. 沿用当前选题卡的主判断：完整对标保留原核心；分部件组装检查各来源能否共同支撑本条新判断；本人观点以当前原话为准。种子词结果卡选题缺观点时，先核对使用者已确认的判断、材料和用户问题；只有使用者另行明确要参考某条视频的具体讲法时，才按该具体内容任务核验原来源。没有可支撑本人观点的材料时如实说明缺口，不从结果卡臆测作者观点。本人明确修改观点时记录变更并重跑选题准入。反认知须说明旧理解遗漏了什么条件，不只加“其实／反而”。
3. 选择一项最能支撑同一判断的本人或学员证据；外部作者案例不得进入成稿。知识库只补证据和边界，不负责给对标题更换观点。
4. 写出判断成立的条件、边界和可能反例。
5. 用一句日常话回答：这条视频看完，观众具体改变哪个理解或动作；再回到口播将要提供的信息，说明常见理解遗漏的条件、原因、关系或取舍，方法型则说明新用法与可用结果。把有关联的建议逐条对照这句判断，解释不了作用的移出本条；不能靠主题名称或多列步骤自证聚焦。按脚本执行标准的立意要求判定，不强迫所有题制造反常结论。
6. 阶段末重新打开已选题、来源和立意卡，按[脚本执行标准的观点立意章节](脚本执行标准.md)提交判定所需的当前产物与来源证据；不使用写作过程记忆代替回读。

## 交接与机器字段

本节只定义展示格式、状态和交接字段；立意是否通过只读[脚本执行标准](脚本执行标准.md)。

- 向使用者输出时必须逐项使用以下固定格式，不得合并成一段、只给结论或省略字段：
  1. **观众原来的理解**：观众当前相信什么、通常会怎么做。
  2. **使用者的新判断**：本条视频唯一要成立的不同判断。
  3. **核心依据／核心证据**：具体依据或使用者／已授权客户事实，以及它直接证明什么。
  4. **成立边界**：判断在什么条件下成立、不适用于什么情况、可能有什么反例。
  5. **用户收获**：观众看完后具体改变哪个理解或动作。
- 执行标准返回`通过`后向状态接力提交`立意完成`，写入`angle_ref`、`old_belief`、`new_judgment`、`evidence_map_ref`、`boundary`和`user_gain`。工具返回`AUTO_CONTINUE_SAME_TURN`后，立即重新读取内容结构Skill并开始结构设计。
- 缺证据或与本人明确立场冲突时，回选题修订应用方案；有价值部件继续保留。题面调研来源先形成自己的观点并补本人真实材料；缺自己的判断或证据时停在相应缺口，不自动深读外部视频。

## 返回、停止与清理

- 被使用者否定的立意不留作并列候选；记录可泛化原因后关闭并清理。

## 独立使用的配置边界

独立用户沿本文件的方法与检查，以自己的已确认任务、原话、真实材料及输出目录执行。使用者身份、业务主题、样本库、专名纠正表、品牌及字幕/字体/美颜/美体/速度/音量数值仅属于使用者自用配置；其他用户保持自己的原片/原工程值或本次明确选定值。没有个人历史样本时校准本轮原话，不虚构过去的修改和效果。不调用公司状态库、自动化或私有客户资料；各阶段凭证保存用户本地记录。

# 内容结构 Skill｜让论证连续推进并兑现立意

- 标识：`short-video.skill.structure`
- 所属Agent：[脚本](../SKILL.md)
- 执行标准：[脚本执行标准](脚本执行标准.md)

本Skill只定义内容拆解与结构设计流程。每个大步骤前先读执行标准对应章节，再读本步；完成后复读执行标准，以完整来源、逐单元分析和最终结构卡验收。

## 触发与输入

- 元数据题面调研的已选题，以已经通过的本人立意、真实论据和边界设计本稿结构；不需要原视频全文，不从标题、介绍、标签反推作者推进顺序。下方对原来源逐单元拆解的步骤仅适用于另行明确采用完整结构参考、且真实完整来源已可读的任务；普通题面来源直接组织本稿开头、承接、论证与收束，并保留实际材料映射。

- 接收已选题的具体问题、题面预期收获和已通过立意的用户收获；将其实际兑现位置写入原结构卡的开头、论证推进、证据及结尾字段，按脚本执行标准第3节逐项核对。适用复盘反馈保留在原应用记录，不另加一种结构卡或把单批高播放作品固化为统一模板。

- 公众号文章改编接收全文与立意，将原文判断、论证和案例映射到本稿段落，按短视频观看理由设计开头和承接；长文标题、段落数量与信息结构不直接作为视频模板。

- 已通过的立意卡；若来源为对标视频，还需要从第一句到最后一句的完整口播内容。可以是带标点且经核对的完整转写，也可以是能够听见气口并带时间位置的完整音频／视频；只有标题、平台摘要、章节、若干字幕画面或分段概括不能触发本Skill。

- 各类来源都遵循相同的本稿基本结构要求；只有本次明确使用完整结构参考时才逐单元分析该来源。先按[表达学习与应用](表达学习与应用.md)召回相关结构与改稿样本；外部来源回读完整作品，本人观点回读完整原话，结构参考来自其他作品时也须回读对应原文。

## 唯一执行链路

1. 先确定唯一切分依据。完整转写已有标点时，以每两个相邻标点符号之间的内容为一个最小表达单元，逗号、句号、问号、叹号、分号、冒号、顿号等都构成边界，不能因为前后意思相近就跨标点合并。完整转写没有标点时，必须回到音频／视频识别真实气口，以每两个相邻气口之间的口播为一个最小表达单元；字幕换行、画面切换、自动分段和AI摘要不能冒充气口。
2. 从第一句到最后一句逐单元覆盖。每个单元记录`单元编号／起止时间或上下文位置／原内容／边界类型（标点或气口）／这部分直接说了什么／作者为什么在这里说／它承接前一单元什么／它给后一单元留下什么`。语气词、重复、广告和看似无信息的短句也要记录，可以判断其目的只是停顿、强调、拉近关系或转场，但不能直接跳过。
3. 做覆盖检查：原口播的每一段文字只能进入一个单元，不能遗漏、重复或重新改写后冒充原话；按时间排列必须连续，非口播静音另行标明。只有完成全部单元的目的和前后关系分析，才可以归纳整条作品的开头、推进、转折、证据、理念、业务说明和收束。将分析保存为整体顺序、段落功能、句子／气口动作三层：每个动作列原文位置、观众此时的疑问或理解障碍、实际表达动作、论证关系与证据、前后承接、可替换内容和不可省略的前提。观众心理为分析假设时明确标记，不冒充评论事实。按选题库维护Skill把有价值的新模式或已有模式的变体关联入结构库，不压缩成固定四五步，也不以现有三条样本作为模式上限。
4. 还原来源实际结构，建立`来源段落／结构功能 → 本稿段落和具体内容 → 保留、调整或不采用及理由`应用对照。完整对标沿用`protected_structure`中有效的开头、推进、证据、转折和收束功能顺序；分部件组装按本稿论证需要逐项映射，验证连接，不能把A的结论强接B的无关案例。本人修改观点后重查结构适配。
5. 以`一个问题 → 一个判断 → 一个证据 → 一次收束`检查内容集中度：这里的“一个证据”指服务同一判断的核心证据链，必要解释、比较或下位论据可以保留。它不是必须按四段出场的模板，不能覆盖对标有效结构、删掉必要因果或把本人判断改成另一个题。回读每段实际内容，指出它解决的同一判断下的理解障碍；只有话题相关却不能说明论证作用的段落移出本条。用正文尝试复述唯一判断和收获，再按脚本执行标准判定；不借后台卡片补出口播未说出的观点。
6. 单独设计前约5秒及紧接的承接；结果判定唯一读取[脚本执行标准3A](脚本执行标准.md)。直接按该标准设计；仅标准边界不清、判断分歧或明确校准时，按表达学习与应用Skill回查评分样本，再执行：
   - **选择入口并区分案例。** 按本题观看理由选择成果交付、直接任务、收益好奇、具体纠偏或成长/类比等适用方式，写出起句与后续一至数句，不强制先有冲突或反常点。将共同需要与后文具体案例分别写明，检查是否被课件、细分职业或专用参数误缩入口；按当前选题准入取舍，非AI来源可借形式不自动取得题材许可。
   - **放宽入口，不稀释主题。** 开头仍直接指向原核心判断，不得换成另一个更泛的道理，不能把“在真实服务中改好产品”改成“向客户学习”等另一条主题。不得用无关热点、空话或夸大承诺吸引无关人群，也不扩大证据能证明的范围。扩大入口不等于增加一段泛论；尽快进入原论证。
   - **判断之后，接住误区、痛点和感受。** 以判断或反常点开场、要纠正一种做法时，紧接着写清三层：观众误以为什么并因此怎么做；这个过程具体增加了哪些动作、返工、等待或选择；观众在这些动作里会出现什么可理解的困扰或感受。感受要由可见处境支撑，例如“一直挂着待确认事项、忙了一天却没有一件真正结束”，不能只贴“焦虑／疲惫”等情绪标签，也不能虚构损失、夸大恐惧或把可能性写成必然。完成认知强化后再接原因、案例或正面做法，不能说完判断就直接跳到抽象原因或好处。
   - **局部修改守住范围。** 使用者只要求换开头时，先锁定原主判断、证据、论证和结尾；仅修改开头及必要的衔接，不借放宽受众重写后文、删掉论证密度或换主题。整合全文时使用明确的原稿版本和替换边界，并核对边界之后的正文是否保持不变；若确需改后文，先说明具体冲突及最小必要改动，不暗中扩大范围。
   - **前句与后句一起检查。** 先写出连续开场，再看起句为何值得停下、后续每句让观众多认出什么处境或疑问，以及怎样接到正文。大白话不等于只留一句；问完不急着回答或切抽象方法，必要的具体动作、代价、感受和本人判断要展开。也不能只加重复抱怨、连续概念定义或无关铺垫。保留本人示范中的直接口吻，形式按本题观看理由选择，不机械套一问一答或统一的多句模板。完成后复读执行标准3A，核对实际开场与第一段正文；局部返修按明确边界比较未改正文。
7. 常用推进可为`误区 → 原因 → 正确方法/本人思考 → 使用者或学员案例 → 收束`，但不机械套模板。
   - 本人真事作为本条核心论证时，回读原材料，把实际处境、卡点、具体动作、转折和当前变化排进连续段落；先让观众看到发生了什么，再解释判断。本人明确表达的痛苦、焦虑或生气可沿真实原话呈现，不能按戏剧模板补造感受。方法设计、当时执行、本次整理和后续计划分开。检查当前批次是否反复使用同一案例，没有不同用途则换已核对的案例或合并。
   - 在本对象原结构卡附至少两种可替代画面材料：可为真实聊天截图、材料与报告对照、实际操作录屏、真实作品或课件；逐项绑定段落、画面内容、证明用途及已有/待补状态。用户愿意提供素材时先给具体选择，不泛问“有没有案例”；不存在历史录像时可用当下录屏并标明，不能假装是过去现场。
8. 用能直接讲出来的话写清每段内容，再逐句、逐段检查上一处留下的问题是否被下一处接住、听众多明白了什么；并列原因、因果、解释、例证与转折必须区分，不能把内容排列顺序冒充因果关系。删掉可任意调换的正确道理和第二个独立问题；保留证明同一判断所必需的解释，不为缩短而删掉连接。只有箭头和概念标签的提纲不算结构通过。
   - **把收获感设计成可直接使用的内容。** 解释型、纠偏型或方法型视频不能只让观众“听懂一个道理”。结构必须把主判断转成具体动作，至少说清从哪里开始、按什么顺序做、用什么标准判断完成；适合时加入可直接照着使用的问题、检查项或示例。建议必须正面解决前文误区和痛点，不能只给“重视、优化、持续行动”等泛化结论，也不能为了显得有用而并列多个无关技巧。
9. 阶段末重新打开已选题、立意、完整来源、逐单元分析和最终结构，先复算单元是否覆盖第一句到最后一句，再按实际段落顺序独立复核问题、判断、证据、承接与收束。开头与收获按第6、8步逐项检查：①不从事案例业务但同样受益的人，是否会误以为与自己无关；②新旧开头分别让人以为本片在讲什么，是否仍指向原判断；③纠偏型开头或使用者明确要求时，误区、误区中的具体动作、痛点与有处境支撑的感受是否真的写出；④只改开头时，范围外文字是否保持不变；⑤观众能否只根据正文复述一个可以立刻执行的做法、顺序和完成标准。任何一项失败、入口放大但正文无法兑现或只讲道理没有可执行收获，均退回相应步骤。不能用分析过程中的自评代替。

阶段末的实际复核须引用当前开头及段落内容，分别说明它建立了哪种真实观众处境、每段比上一段增加了什么，以及承诺的收获具体落在哪段。只看“入口／案例／方法”等功能标签不能给出通过。若作者特有经历被当成观众共同误区，回到立意修正受众前提；若顺序、重复或方法收获不成立，留在本阶段修复。逐字稿完成后还须按[正文独立复核](逐字稿.md)回查真实成稿，结构卡的通过不能跨到改写后的正文。

## 交接与机器字段

本节只定义展示格式、状态和交接字段；结构是否通过只读[脚本执行标准](脚本执行标准.md)。

- 向使用者输出时必须逐项使用以下固定格式，不得只给结构名称、概括性模板或直接跳到逐字稿：
  1. **开头前约5秒**：具体讲什么；本次观看理由是什么；怎样让观众立即知道这条视频在回答什么问题。冲突或反常点仅在适用时列明，不为填字段强造。
  2. **开头后的承接**：下一段具体讲什么；观众的误区、误区中的具体动作、痛点与有处境支撑的感受是什么；如何强化对问题的认知并进入核心判断。
  3. **核心观点**：本条视频唯一核心判断如何明确说出，不能只写抽象标签。
  4. **论证推进**：按实际出场顺序逐段列出；每段都写清`具体讲什么／这一段的作用／怎样承接上一段／怎样引出下一段`。解决方案段另写清观众可以直接采用的起点、步骤、判断标准和示例，证明正文具有具体收获而不只是在解释现象。
  5. **核心论据／证据**：具体描述使用什么使用者或学员事实、放在哪一段、直接证明核心判断的哪一部分；案例前说明要证明什么，案例后扣回判断。
  6. **结尾收束**：具体怎样回到核心判断、让观众带走什么；不得开启第二个问题、第二个行动建议或第二次价值升华。
- 执行标准返回`通过`后向状态接力提交`结构完成`，写入`structure_ref`、`opening_ref`、`progression`、`evidence_position`、`close_ref`和`structure_application_ref`。工具返回`AUTO_CONTINUE_SAME_TURN`后，立即重新读取逐字稿Skill并开始写稿。
- `structure_application_ref`指向本对象实际应用对照文件，含资产／来源、原结构功能、本稿位置及调整理由；未命中合适结构时记录检索范围和新结构依据，不能空写“已参考”。状态工具检查本地文件，内容标准检查映射是否真实。
- 缺完整对标内容、带标点完整转写或可识别气口的完整音频／视频时先补读；无法补齐就停在本Skill并明确缺口，不得用标题、AI摘要、字幕抽样或作者大意先生成结构和逐字稿。结构跳跃也退回本Skill，不交逐字稿。

## 返回、停止与清理

- 新结构被采用后删除未采用结构候选和重复检查表；保留最终结构与必要来源证据。

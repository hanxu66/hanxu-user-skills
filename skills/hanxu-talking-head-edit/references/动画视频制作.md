# 动画视频制作 Skill｜从已确认逐字稿生成视频

- 标识：`short-video.skill.animation-video`
- 所属Agent：[剪辑Agent](剪辑Agent.md)；独立调用也由同一Agent管理制作状态。
- 结果判定：[剪辑执行标准](剪辑执行标准.md)。
- 授权与来源：动画制作独立Skill及公众号入口确认（独立模式使用本次材料与本地记录）。

本Skill维护动画主画面的操作步骤、参数及制作交接；是否通过只读[剪辑执行标准](剪辑执行标准.md)，本Skill不另立通过／失败判定。口播原片上的局部辅助动画仍读[口播剪辑](../SKILL.md)，不在这里重写普通口播方法。

本人明确提出产品/课程/企业官方介绍或相应动画风格时，先由剪辑Agent绑定[产品介绍视频类别](产品介绍视频.md)，按其介绍结构与模型分镜组织，再回本Skill制作。该类别不替换故事型/PPT型，也不作为其他动画的默认风格。

## 独立使用的配置边界

本文件下述品牌、声音、画幅和头像参数为使用者自用的已确认配置。独立使用者用自己的已确认素材、音源、样式和交付目标；没有历史样本时只校准本次需要的构图或声音，不复制使用者身份、默认人物素材或私人声音参考。没有已授权可用的声音生成能力时，沿用本次已有录音或保留真实缺口，不声称已获得本人声音。原声映射、类型区别、头像与字幕分区、完整时段检查和交付结论边界继续适用；不调用公司状态库或私人反馈源。

## 动画类型与调用

接收剪辑Agent绑定的`animation_type`及选择原话，制作前读取[动画类型与分镜方法](动画类型与分镜方法.md)的对应类别。故事型以人物在场景中的行动、事件与结果变化推进，PPT型以动画页面和结构化图解推进；两者相应讲解段均以动画为主体，并包含本人小圆头像。故事角色不代替本人头像，给真人大画面上方加窄幅图解不代替PPT型主体形式。类型选择由本人本次要求或同对象有效记录决定，不按工具、配色或制作难度代选；定义或画面理解仍不清楚时，先讨论具体分镜或代表片段，不自行批量扩展。

此类型入口同样供口播局部动画调用，只提供分镜方法；普通口播内容剪辑、局部范围、头像、交接与导出仍执行原主责Skill。故事型不固定为简笔画、卡通机器人或单线条，视觉成熟度与素材选择按该类别方法处理。命名授权见本人确认（独立模式使用本次材料与本地记录）。

## 两种调用入口

1. **工作流接入：**接收脚本Agent交付的当前逐字稿、脚本状态、本人采用依据和`production_form=animation`，制作从本Skill开始。
2. **独立调用：**使用者说“把这段逐字稿做成动画视频”即绑定本次稿件及制作授权。将全文保存到本对象目录，记录`entry_mode=standalone`、`script_ref`和`script_approval_ref`，直接进入本Skill；不补造选题、立意、结构或拍摄完成记录，不要求重跑找题。只有文章尚未改为稿件时，回选题／脚本Agent按公众号路线完成改编。

开工锁定对象、稿件全文及哈希、来源、修订、交付范围、音源、动画类型及选择依据、视觉样式。稿件有占位、截断或明确缺口时只补必要信息；本人已确认的观点不因独立制作再改写。

默认沿用本批已确认的竖屏动画视觉语言、本人声音参考及最新语言与配音风格基准（独立模式使用本次材料与本地记录），音源也可采用本人本次完整录音。使用者本人的故事型／PPT型均记录`avatar_mode=circle`并执行本人小圆头像章节，沿用已确认的间歇节奏与构图，不自行省略。只有本人当次明确不加头像时才记录`avatar_mode=none`及`avatar_waiver_ref`；素材暂未找到不视为豁免，先查同对象旧工程与已认可素材，再处理真实缺口。未指定新形式不重新设计，也不要求重新拍摄。独立调用默认交付MP4审看版；本人明确要求正式成片时，接Agent规定的正式工程交接路线。

## 第一步：稿件与画面方案

1. 读取当前完整稿件；独立调用以已确认稿件为制作依据，不额外要求公众号原文。涉及文章改编时回读对应原文证据，再把稿件按实际语义分段，读取已选[动画类型的方法](动画类型与分镜方法.md)，建立“原稿段落 → 需要理解的关系／变化 → 对应分镜与动作 → 配音段 → 字幕”的对照。公众号原文链接失效时使用已核对的本地全文；缺正文不从标题补造观点。
2. 锁定画幅、已认可样式与头像选择。默认审看版1080×1920、30fps；其他画幅按本次明确要求。正式导出参数引用[口播Skill的正式交付参数](../SKILL.md)，不在本文件另定一套正式参数。
3. 第一镜头沿用下述已确认的左对齐大标题，醒目清楚；约1至1.2秒后进入核心观点，2至3秒内完成首轮呈现。后续分镜执行已选类型：故事型按内容中的动作与状态变化推进，PPT型按判断、对比、因果、流程或模型组织；两者均保留原文真实关系与实际项数，不统一套四点。PPT型的同组并列概念由主题引出后同时出现，加克制的整体动画；故事型的发生顺序则跟随原声，不为套并列版式打断连续过程。
4. 默认沿用下述使用者已确认的深色底、米白正文、橙色强调风格；具体角色造型、物体细节和构图按已选类型及内容设计，不把配色、代码制作或小样认可当成简笔画造型的长期要求。用ChatCut可编辑动画源码和属性建立画面，记录实际资产绑定；保存本条`animation_plan_ref`。留出独立字幕带与平台安全区；纯动画不套人物美颜、姓名/title或嘴型处理。
5. 复读剪辑执行标准对应章节，核对方案与稿件关系后继续。

## 已确认视觉风格与安全布局（2026-10-08）

使用者直接要求：“把这个视频的动画风格记录下来，包括字色、字体、字号、位置、底色，然后存到对应的skill里边。以后都要这个颜色的风格”；同时指出字幕太靠下，要求调整并记录。此节替换此前浅底蓝色样式，作为后续动画视频默认风格。其他本人明确指定的视觉形式按当次授权执行。本人故事型／PPT型的头像要求按本Skill调用入口落实；未启用动画的普通口播不因此增加头像。

字幕上移需要同时核对动画与头像，不能只将旧字幕放到会碰撞的区域。采用真实口播循环时，源声静音，不声称与新稿逐字嘴型同步。新取材重新检查整段头顶与肩部、圆内覆盖、身份字／旧字幕、动作和源区间；上述圆内位置只是已确认起点。

清晰度检查分开记录原生资产像素、导出像素、实际编码参数和上传结果。至少在相同显示比例下比较实际导出标题、细字和头像；“4K”、文件变大或码率变高不能单独作为清晰度已修复的证据。原生导出无法控制码率时，将已重新渲染且像素核验通过的母版交原生剪映做编码输出；保留可编辑动画主工程，不把编码时间线的单个视频说成完全可编辑图解。未实际上传验证时，不宣称视频号的低清提示已经消失。

## 第二步：画面与声音小样

1. 已确认的视觉模板与音色沿用其真实采用依据，直接继续本条制作；只为新样式、新声音或新反馈制作代表片段。
2. 新视觉样式选能暴露主要问题的真实内容，在原生工程生成合成预览，检查长标题、复杂关系、最长字幕与适用的圆头像；新声音用同一短稿生成对照试听。两个样本分别保存采用依据，不能把画面认可当成声音认可。
3. 按执行标准完成可执行检查，必要的新审美／新声音判断交使用者；收到对应确认后继续，不扩展未认可候选。模板复用的逐条检查保留，但不重复增加人工确认。

## 第三步：完整配音与去气口

使用者已明确要求本人声音的后续生成持续采用语言与配音风格基准（独立模式使用本次材料与本地记录）最新有效内容。每轮先读取并冻结全文、版本与哈希，锁定稿件和参考录音，再按每段实际含义选择自然解释、判断转折或列举的参考区间，写入朗读分组、重点词、连续承接和去气口计划。按基准区分原始录音与成片声音，记录每个音源是否已经加速；去气口后只应用一次目标倍速，不用固定字速降低局部速度，不给重点词拖腔或插入静音。音色和节奏候选未获本人试听认可时，不再全批扩展该候选；先提供同文本短段与本人有效声音对照。仅改变分组和标点不改核心正文；临场增词、错读和失败重录不自动写入稿件。模型支持的表达控制据实际接口核验，不给不支持的风格标签冒称已生效；通过参考音频、语义分组及音频检查落实可执行部分，生成结果和人工试听分别记录。个人表达数据只在基准文件维护，不在本Skill复制一套风格数值。每次返修保留旧版，记录基准与参考区间的实际应用；基准修改后旧计划必须重新核对，不能复用过期哈希。

1. 读取最新声音基准，保存本轮全文快照、哈希、已确认声音参考和`voice_plan_ref`。原录音、已去气口录音、已加速录音分别标记；目标速度只从最新基准读取。
2. 在本人已授权的生成能力中，以同一有效声音参考按完整语义段生成，记录真实支持的参数和本条结果；既有可用录音则先核对全文。只有实际音色或字音需改变时重生成相应片段。音源缺失但画面可做时只保存静音预览与待配音状态。
3. 用全文转写、词时间码、波形和语义核对漏读、重复、专名与错误发音。同音写法可保留原稿并记录核查证据；真正漏字、错音或变声从对应片段修复，不能只改字幕掩盖。句首弱读字缺失时，可生成短引导语后沿词界剪去引导语，保护目标词头，再重新转写核对；原始尝试与裁切区间留在本条记录，成片只保留原稿正文。
4. 去掉几乎全部句间与段间气口，完整保留词头、词尾和必要字音过渡，合并成连续完整配音。只执行一次基准规定的最终倍速；不按固定字速局部减慢，不拖长重点词，不为画面撑时长补静音，不用变调或整条加速掩盖已失真的声音。
5. 保存完整WAV、有效语音时间码和源音频到成片的映射。新音频确定后才锁定最终画面时长；复读标准并记录机器文字核查与本人实际试听各自的状态。

## 第四步：音画与字幕同步

1. 以实际配音及有效时间码为唯一时长基准，顺序放置动画段落，保持一条有效主声音轨；原视频原声模式保持其真实内容与源映射。字幕按完整词组与相对完整语义分卡，不把一个词拆到前后两张卡。
2. 按已确认模板使用白字与清晰深色描边，字幕与动画及适用头像分区。每张字幕以真实字体、字号、显示宽度和手机观看尺寸查看；超宽时按完整词组拆卡，不通过缩字或挤字维持长卡。
3. 从实际原生Viewer读取合成画面，核对开场、语义转折、长字幕、头像入退场和片尾；动画素材属性、音源绑定、时间线总长与有效区间逐项读回，实际像素不因字段正确而省略。
4. 用原生时间线安排声音，动画和字幕跟随声音；语义分段不增加段间空白。帧网格需要尾部补齐时只记录整条末尾不足一帧的尾差，不逐段补齐造成新气口。
5. 本人故事型／PPT型执行下一节的小圆头像制作；本人当次明确不加头像的例外绑定原话后，才直接进入封面与导出。复读标准，完成本条实际同步检查。

## 本人小圆头像

本节承接原口播Skill的“动画配音与间歇圆头像策略”，使用者本人的故事型／PPT型默认均执行。`avatar_mode=circle`是本人讲解者的真实小头像，不是故事中的人物角色。原视频有声则用对应原声及同修订画面；文字配音则用既有真实口播循环、源声静音，不记录为新稿逐字嘴型同步。横屏成片仅作头像取材时不启动双版本制作。保留以下已确认的间歇节奏，不自行改成全程常驻；本人当次明确指定其他位置、节奏或不加头像时绑定依据。制作有真人源的头像前，按口播Skill第五步核对来源曝光与肤色，不能把未经匹配的过曝人物缩小后当成已处理。

1. **按来源选择头像画面。**原视频有声音时，用当前已剪辑的原视频画面作为头像，出现段与原声音的同一语义时间线对应，不另换不相关嘴型；先按普通口播步骤完成本条内容与声音剪辑。公众号文字的虚拟口型优先从本人已发布横屏中长口播视频的剪辑成片取材，核对本地文件、发布／归档证据和同修订，取稳定中远景、自然说话与轻微动作，避开大幅移动、原身份字、切镜和遮脸，不误用原始拍摄版本或其他人像。两类都记录实际源区间与画面对应；新片重新选区间，不复制样例媒体ID或固定源时码。
2. **圆窗与人物构图。**人物保持较小，保留肩部／上身和适量背景，减弱细小嘴型的可辨程度；只移动圆内视频调整头部，不把人物放大成大头。圆窗由单层视频完全覆盖，外部透明，不用上下背景填充条。代表性自然姿态的头顶距圆顶约为直径的15%至20%，再检查整段动作避免切头。1080×1920样例起点：圆窗左770、上1190、直径220；内部16:9视频高度280、宽约497.78、水平居中、top=-20。其他画幅等比换算，新取材按真实人物位置调整。视频覆盖与人物大小同时通过改变源构图和裁切实现，不为消除露边把人脸强行放大。实际字幕与身份区单独留空；本模式不用同步原口播的左上角大圆窗或真人全画面开场。
3. **间歇出现。**开头默认露出20秒，可按本条节奏在15至20秒内安排；之后默认再在两处内容转折／本人实践段露出，每次约6至8秒，其余时段隐藏。样例实际为0–20、39–47、52–60秒，后两处属于样例内容位置，不硬套所有视频。每次短淡入淡出，30fps起点约5帧；头像不全程常驻，不为每个关键词重新出现。
4. **制作与取材防错。**动画、圆形遮罩、圆内视频缩放／位移、出现区间和正式文字保持可编辑；沿用Agent规定的主工程与交接路线，ChatCut原生MP4仅作为画面审看或取材证据，不冒充剪映正式成片。用原生剪辑sourceIn定位后核对实际源帧；MG素材内部非零播放偏移若未在像素中证实，先用原生裁剪导出已核查的静音短素材，再从短素材0秒绑定圆窗。原视频原声模式的每次露出均保留对应源区间与剪辑后时间线映射，不复用不对应的循环嘴型；公众号文字模式可循环复用核查后的短素材。不得只因偏移字段正确就声称已选到目标区间。调整人物上下位置只改圆内位移，保持已确认圆窗、缩放、时段和动画不变。

按实际配音时间安排每次露出；人物位移只改圆内位移，不扩大成大头像或改变已认可时段。2026-10-08的字幕安全区修正只上移圆窗整体位置以腾出字幕带，圆内缩放、头顶留白与间歇策略保持原值。本人明确要求真正数字人或逐字口型同步时，另行核对该能力与授权，现有循环头像不承担该交付。

## 第五步：封面、导出与复查

1. 独立制作主封面，不直接把含页码、实时字幕或进度线的动画播放截图作为主封面。纯动画封面用本条动画视觉与主题文字构成，保留同修订内容，不强制取人物帧；圆头像模式读取已有被本人认可的完整封面参照，再按[口播封面方法](../SKILL.md)制作。动画配色、圆头像素材或视频内头像位置的认可，不能当作封面构图采用依据；不得把视频内小圆头像放大后另排成未经采用的封面。具体失败构图与复用边界见封面否定反馈（独立模式使用本次材料与本地记录）。纯动画封面采用同条已确认动画样式，重新打开检查安全区与手机可读性。
2. 保存ChatCut可编辑工程、完整配音、SRT、封面与版本清单。审看版使用ChatCut原生视频导出：MP4、H.264、1080p、时间线30fps，输出路径实际回读。视频渲染与工程编辑使用原生工具，不改成外部拼视频；FFmpeg等音频处理、帧提取和解码核查仅作辅助证据。
3. 确认导出任务已结束且文件写完，再读取完整视频流、帧数、实际画幅、声音与时长，核对导出声轨确实对应当前完整配音。重新打开实际MP4及封面，正常速度全片审听／审看；AI听辨受限时只标记相应缺口，继续可执行的全文、时间码、音轨及画面检查，交使用者判断音色与演绎。
4. 交付MP4审看版、封面、WAV、SRT、可编辑原生工程和当前修订索引；审看交付保留`剪辑中`并记录`review_delivery_ref`，不提交`可发布`。正式范围按剪辑Agent完成可编辑剪映交接与收尾，再由同一执行标准判定；工具阻塞记录在正式交接，不倒推为已完成的原生审看导出失败，不自动购买、充值或升级。
5. 复读[剪辑执行标准](剪辑执行标准.md)，核对真实文件及范围后由剪辑Agent交付；内容、配音、字幕或画面有缺陷时只返对应步骤，并更新实际受影响的下游产物及检查。

## 制作字段与接续

- 开工：`production_form=animation`、`script_ref`、`script_sha256`（当前稿件文件字节哈希）、`script_approval_ref`、`animation_plan_ref`、`scene=animation`、`project_ref`；独立入口另记`entry_mode=standalone`。已确认稿可由剪辑Agent直接登记`剪辑中`，不补造`已拍`。
- 动画选择与分镜：`animation_type`、`animation_type_source`（本人选择原话或同对象有效继承记录）、`animation_scope`、`visual_style_ref`；类型按本人选择使用中文值。`animation_plan_ref`绑定本条原话、人物／图解主体、分镜、动作事件／结构关系、时点、实际资产和本人小头像时段；不加头像的明确例外另记`avatar_waiver_ref`。制作与交付记录沿用同一选择。
- 声音与成片：`voice_plan_ref`、`audio_ref`、`srt_ref`、`avatar_mode`、当前工程和导出实际路径。`source_compare_ref`指原稿／原声与最终内容对照，不强制存在真人原片。
- 审看交付：`delivery_scope=review`与`review_delivery_ref`，说明本人待判断的实际范围；正式交付记`delivery_scope=formal`、`formal_handoff_ref`（正式工程交接记录），才提交`可发布`；保留原有全片实播、封面、工程完整性与质量收据要求，以及真实`audio_ref`、`srt_ref`和`voice_plan_ref`。
- 发布事实、数据任务交接和到期复盘由既有Agent继续接力；制作授权不代替发布授权。本Skill不改变研究自动化、源文章工作流或发布调度。
- 各对象独立记录读取与复查，不用第一条检查代替全批；软件恢复按剪辑Agent既有上限，从最后成功检查点继续。运行环境、模型和共享声音参考保留可恢复路径，批次中断后先核对文件、哈希及未完成动作，避免重复生成或重复创建工程。

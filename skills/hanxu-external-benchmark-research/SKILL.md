# 韩叙 · 短视频选题调研助手

不知道下一条拍什么，想从指定账号和关键词中寻找选题启发。

- **适合谁**：抖音、小红书创作者，以及需要持续研究受众兴趣的人。
- **提供什么**：研究平台、对标账号或关键词、时间范围、你的业务方向。
- **得到什么**：来源明确的选题调研卡、候选建议、已覆盖范围和资料缺口。
- **使用条件**：需要可用的平台访问或你提供的真实结果资料；格式检查脚本需要 Python 3。只读标题、介绍和标签时，不推断视频完整观点。

先看[中文使用介绍](README.md)。执行时遵循下方原方法与配套标准。

## 使用者配置与独立使用

本文件同时保留使用者内部调用和独立用户模式，方法不分叉维护。使用者自用继续读取原对象、样本与状态工具；独立用户只使用自己提供的题目、观点、来源、正文、素材、授权、品牌及输出目录，不能读取使用者的私人库或替用户补造个人经历。下文使用者身份、业务方向、个人样本、品牌和参数是个人配置，独立使用不自动继承；使用者自己的原话、修改和已授权案例替代本人资料。原方法的事实、证据、适用边界与检查仍执行。

独立用户在自己的输出目录保存来源清单、版本、阶段结果和检查记录，可自行命名本地对象；不要求使用者内部对象ID、公司状态库或状态命令。材料已经齐全时按原顺序连续推进，确实缺失才补最小输入。内部Agent/上游/下游指本方法的阶段职责，独立任务按本次已授权范围执行，不需安装整套经营系统，也不自动建立定时任务或发布。安装包由本文件及其现有依赖生成；修改回原文件，导出目录不是另一份维护主档。

独立模式由本次实际账号/关键词/平台和范围开始，检查点写用户目录，不接使用者自然周线程或09:00自动化。保留完整报告及逐条题面卡；日常不下载或转写视频。另有明确全文任务时分别记录完整读取、部分读取、仅题面，不把已有全文当本轮新读。格式检查使用scripts/check_short_video_research_delivery.py，无私有选题库时只查实际卡片；真实来源和效果另验。

每轮实际执行及断点恢复，先读取本Skill和[选题执行标准第1/2/2A节](references/选题执行标准.md)，再采集、研究与交接；第2A节是低粉高互动及弱互动排除的唯一判定来源。内部调用同时按总入口及选题Agent完成当轮读取，独立使用读取本Skill和随附标准。在原运行记录保存实际读取时点、路径、修订与范围，不以历史读取或聊天记忆替代；每个大步骤后复读适用标准检查真实结果。


- 标识：`short-video.skill.external-benchmarks`
- 修订：`2026-10-18-wider-first-screen`
- 所属Agent：选题（独立模式使用本次材料与本地记录）

账号清单与检查点读取对标账号清单（独立模式使用本次材料与本地记录）和监测状态（独立模式使用本次材料与本地记录）。研究授权不等于代选、写稿或发布授权。

## 独立任务范围

本次平台、账号/关键词、时间范围与检查点由使用者指定，保存实际覆盖与失败断点，不创建公司的定时任务或线程绑定。

## 唯一执行链路

1. 锁定本次账号、平台和范围，回读旧库与检查点。保存具体作品ID/链接、作者、标题、发布介绍、标签、日期与可见互动；标题或介绍被截断则标范围，缺标签如实未取得。指定账号来源来自账号作品区，不能把推荐流当新作。
2. 先按身份、短视频类型、日期和本次范围检查，再执行[第一层筛选与待研究对象](#第一层筛选与待研究对象)，区分原料的研究价值与整题推荐资格；AI解释和源文字分开，不填未知作者观点/论证/结构。标题与介绍可能不一致时保留原字段，不拼成伪造正文。
3. 将题面调研卡交选题库维护与推荐（独立模式使用本次材料与本地记录）：补旧条目或储备有复用价值的问题、角度和题面表达；本次需要候选时在同一Skill内筛选推荐。把当前结论与实际来源返回种子词Skill继续未完覆盖；发现一题不提前停止授权范围。
4. 用下节题面卡与唯一库快照直接交实际查询、业务启发、当前推荐/储备和缺口；分别说明指定账号、抖音、小红书的真实覆盖。无需作者正文也可完成题面调研，0候选仍可有价值积累。
5. 复读标准核对字段真实性、库行、推荐与送达，保留断点及清理凭据。文件存在与实际消息送达分别记，周期和调度沿上节。

## 第一层筛选与待研究对象

本节是关键词和指定账号来源共用的初筛操作；来源与原料沿选题执行标准第1/2节检查，收录与正式推荐分别按第3/3A节和第4/4A节判断。第一层先找值得研究或保存的问题、角度、题面表达和材料用途，不提前套用整题正式候选门槛。

暂缓理由须指向本条实际问题、缺口及恢复条件；疑似重复须说明对应旧题与新增／缺少的材料，不以统一的“未形成独立用途”加原题替代逐条判断。已有材料足够排除或归并时当轮处置。收尾运行现有题面流水线的`screen-audit`检查重复暂缓模板；告警消失不等于语义初筛通过。仅留本轮线索而未入库时在原卡标`asset_action=weak_signal_only`，不报入库，也不得用它豁免正式候选的库关联。

1. **分开记录两个判断。** 在原卡的`interest_judgment/application`写当前能识别的研究价值和拟用位置，在`missing`写来源范围、适配或增量缺口。`decision/disposition`沿现有状态填写；尚不能正式推荐时，不把它直接改写为素材无价值，也不新增评分、比例或研究数量配额。
2. **四类边界逐条核对。** 标题泛AI时，先找已有介绍中的具体任务、阻碍或可用表达；场景偏细分时，分开看原案例人群与可迁移问题；出现本人不用的国内工具时，分开看工具专用操作与可借的问题/场景；疑似重复时，按核心用户问题比较新增角度、例子和题面表达，再决定补旧行或另判独立问题。仅用“泛AI／偏细分／国内工具／重复”作整类排除理由时，回到当条说明具体依据。
3. **先利用已取得资料。** 原卡已有足够原文就据此判断；只有补字段会改变当前用途或处置时才补最小公开介绍、标签、身份或日期，不因放宽入口强求全部详情。访问受限或介绍缺失时保留准确范围和接续条件，按既有恢复规则停止或继续其他来源，不据未知内容作无价值结论，不下载或转写补齐。
4. **分类保留并接回唯一库。** 有明确、可追溯复用价值的，连同来源、当前用途、不能直接推荐的原因和重新评估条件交库维护与推荐Skill，按标准存储备、待补或只借部件；同题有新增材料就补旧条目。同源同题且无新增用途仅保留去重关系；尚说不清具体用途的保留弱线索与缺口，不为扩大库规模编造资产。非AI素材可按实际证据保留题面表达，不能因此进入当前AI正式候选。
5. **最后单独复核推荐。** 在原卡记录实际点赞、可见评论/收藏、粉丝或未知、观察时点及作者比较依据；按选题标准第2A节单独给出互动判断、放宽理由或待补项，再交库维护与推荐Skill按第4/4A节完整判断；人群、广泛性、增量、真实AI应用、成本、语义去重和本人明确排除继续生效。不得把国内工具素材包装为本人亲测、把细分个案扩大成普遍结果，或从标题补出未知作者方法与结构。未过推荐门槛但有价值的原料继续保存，不自动写稿。
6. **收尾与复查。** 从本轮原记录检查上述四类拟排除对象是否有充分依据，保留原判断、复查理由、来源范围、库关系及待补项；发现同类误筛时修正受影响条目。下一轮先回读这些用途与缺口，只在新资料、明确用途或访问条件变化时补查，不机械重读全部旧卡，不扩大已冻结查询范围。分别交研究价值、库贡献、正式候选与未完成来源，不能只报新候选数。

## 同轮作者信息复用

同平台同作者的本轮已核实主页、粉丝与身份可复用来源及观察时间；作品日期和互动分别取得。同名作者、不同平台不合并。未知粉丝不写低粉，未知播放不算播放互动率；未有形式证据不凭头像认定真人。

## 题面资料获取的工具入口与接力

固定采集沿种子词Skill的OpenCLI入口，已有可读题面直接复用。需要补介绍/标签时只读取公开详情元数据，不调用媒体提取、下载或ASR。原采集与公开详情保存同一运行目录、作品身份、来源时点及哈希；一个入口受阻按种子词Skill有限恢复，字段不可得保持缺口，不用正文代替。

采集后使用`short_video_seed_pipeline.py init/screen/metadata-research/validate`；`metadata-research --analyses <本轮source-cards.json>`接执行者实际题面分析，验证冻结来源、原文字段和处置。报告用`short_video_research_ops.py render`生成。历史全文工具不属于本次找题调用链，媒体获取需要另行明确的完整内容任务。

## 题面复用与来源分离

同一作品的已存标题、介绍、标签可按身份、版本、观察时间复用；易变互动和实际日期按本轮需要更新。历史已读正文保存原时点事实，日常题面调研不要求回读或使用它，不把历史全文研究算成本轮新读。AI应用建议、本人观点与作者发布介绍分开；题面兴趣、入库、候选、选择和发布效果分别记录。

## 交接与机器字段

卡保存`platform、id、source_route、discovery_route、query、title、metadata_text、tags、author、published_at、observed_at、visible_like_signals、analysis_scope、metadata_evidence_ref、metadata_evidence_sha256、metadata_excerpt、metadata_reviewed、metadata_checked_at、topic_question、interest_judgment、decision、application、missing、disposition、library_ids`。未知项带原因，不填假值；`analysis_scope=metadata_only`，`viewpoint_status=待观点立意`。关键词来源保留`source_route=seed_search`；指定账号保留`source_route=benchmark_video`与`discovery_route=specified_account`，路线不代表全文已读。

## 选题调研结论的对话呈现

短视频与公众号分别执行各自工作流，分别统计来源、研究、入库、候选和实际效果，分别交付独立报告。同一对话同时索取两边结果时，按公众号一条、短视频一条组织，每条包含自己的核心效果、推荐、完整库与缺口，不使用跨平台合并总表或把另一边的运行算作本工作流完成。

用普通标题、编号、短段落和表格呈现，面向本人回复不用星号加粗。2026-10-18本人确认的交付顺序固定为：核心效果数据 → 重点推荐 → 其他可选题简表 → 本轮新增／更新材料简表 → 历史与未变化储备折叠 → 本轮效果判断与下一轮重点。全部在当前对话直接可读；原生折叠或对话内嵌呈现可以使用，不另建附件、报告链接或独立预览要求本人打开。没有条目的简表不设空栏目。

1. 核心效果数据先给一张小表：本轮范围与实际覆盖、取得的来源数、实际研究数及读取深度、新增正式候选、旧候选复核、本轮入库与旧题补充、当前库总量及状态分布、关键未完成项。前后轮次、去重前后、发现与已读、新增与存量分别注明；复查旧来源不算新发现，不把关键词命中或卡片数当全文研究数。耗时、成本和采用／发布／传播效果只有实际证据才报告，未知直说，不拿测试数或来源点赞代替工作流效果。
2. 重点推荐从真实通过正式候选标准的当前可选题中，按本轮建议优先顺序选1—3题详细展开；不足3题不凑数，0题明确没有符合标准的正式候选。每题以题目作小标题，说明推荐顺序及理由、为什么值得写（具体读者问题）、准备写什么（拟用切入点与读者收获）、仍缺的具体材料及使用边界、可点击的原作来源。排序属于AI建议，不冒充本人已选；没有依据不推断流量或效果。生产阶段才补的演示等材料如实区分，不借呈现要求增加候选门槛，也不把材料待补称为可以直接完成全部生产。内部ID和逐字段检查不搬到前台。
3. 选题库从唯一主库读取，默认只展开本轮新增、本轮更新和当前可选条目，按库ID去重。重点推荐计入当前可选且只展示一次；其余当前可选题用“题目｜当前状态｜拟写角度｜来源”简表；其余本轮新增／更新材料用“题目｜当前状态｜具体缺口与再考虑条件”简表，不把所有条目重复展开成推荐卡。已写、已发布、已选生产中、已拍、暂停、否定或退出的历史状态优先放入默认关闭的折叠区，即使本轮补过来源也不重新挂为可选；未发生变化的其他储备另放默认折叠区。折叠标题注明类别和条数，点击可展开全部实际行；核心效果、重点推荐和本轮变化／当前可选保持展开。重点推荐、其他可选、本轮其余变化、历史、未变化储备互斥且合计等于库总量，不删库、不改原状态。
   在支持对话内交互的环境，使用本对话内的原生折叠控件，不另给附件、页面或链接；核对默认关闭、点击展开和窄屏阅读。展开操作只影响显示。没有可核对的本轮变更清单时如实说明，不能把全库当成本轮变化。普通标题与标签不使用星号加粗。
4. 结尾简述本轮哪些环节有效、主要瓶颈、数据能证明什么及仍未验证什么，再给一个下一轮优先方向。建议与已执行事实分开，不因写了下一轮建议就自行重跑。重要储备的缺口与再考虑条件、重点题的读者收获、推荐排序理由、工作流效果判断与下一轮重点这四项补充必须有实质内容，适用位置已在上方规定；未知直说，不填空泛评价。0候选也交核心数据、真实新增／更新、完整分层库和主要原因；本人要求深研时在同一对话展开对应部分。

发送前按上述顺序回读实际呈现：数字与本轮记录一致，重点不超过3题、其余当前可选未漏，条目不重复，折叠默认关闭且能展开，未变化储备没有挤占默认阅读，窄屏可读。后台完整资产与候选凭证继续保存；此处简表是调研结论摘要，不取代资产结构或放宽正式候选标准。旧格式草稿或工具输出不能直接视为最终交付，须按本节补齐和检查后发送。

短视频只据标题、发布介绍、标签判断题面价值；作者口述观点和结构未知。研究范围相同的限制集中说明一次，单题仅补特殊缺口。

## 返回、停止与清理


- 未入选且无学习价值的视频只保留去重索引；已入三库的来源、完整内容和必要分析保留为可回读证据，不能因该题不拍而一并清理。
- 每次运行在交付完成、失败收口或保存续跑断点后执行界面资源清理，归属与关闭步骤只读种子词Skill的资源清理（独立模式使用本次材料与本地记录）：关闭本轮启动且归本任务所有的抖音／小红书客户端及逐个关闭本轮新开标签；严禁关闭整个浏览器、浏览器窗口或运行前已经存在的标签。用户原本打开、正在使用或无法确认归属的资源保持不动并记明原因。阻塞续跑也先清理本次触发产生的资源，下一触发再从断点重新打开所需入口。
- 清理后分别记录`抖音客户端是否调用及关闭结果`、`小红书客户端是否调用及关闭结果`、`本轮新开网页标签及关闭结果`、`其他本轮启动资源及关闭结果`；没有使用的项目写`未使用`，保留资源须注明归属原因。清理记录交选题执行标准验收，缺失或本轮自有资源未完成清理时不得提交当天研究完成。
- 已被否定的改编题不反复提交；源作品仍可保留为研究资产，但不得当待反馈候选。
- 指定账号检查与种子词Skill要求的双平台逐词覆盖、话题交付均已完成且推荐话题为0或不足时，正常停止；下一次自动调度仍是次日09:00。不发起同日完成检查或静默空任务，不把“没有合适选题”误记为运行失败，也不为了产题重复抓取同一批账号。
- 整轮因设备层、控制层、应用层或平台层阻塞，且主样本仍不足、选题接力未完成或完整报告无法送达时，不把计划时间记为完成；先按本Skill的入口顺序和有限自恢复处理，并按真实失败层级记录。有限恢复后仍是同一访问障碍时保持每日09:00，不增加同日自动触发；下次从成功断点及变化证据继续。完整报告送达后即使仍有零散缺口，也保持仅次日09:00。
- 向使用者交付了本日实际研究结果后，记录触发来源、北京时间日期、结果边界和待回读的对话；下一次触发先核实用户可见回复并登记消息凭证。即使核心研究尚未通过质量验收，`当日已交付结果`也关闭当日自动研究闸门；不能再用“未完成”推翻这一停止条件。仅有内部文件或任务状态而未向本人交付实际结果时，不伪称已送达。
- 连续两次全量运行都无法覆盖账号清单，或账号身份、授权范围、抓取方式出现关键冲突时停止扩大采集，向使用者反馈阻塞、已完成范围和需要确认的唯一问题。
- 使用者明确某个账号或方向不再研究时，更新账号清单或当前规则后停止采集；不得仅因一条作品表现差而自行删除账号。
